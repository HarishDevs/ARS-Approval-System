# 02 — Module and page inventory

v1.8.0 has **74 pages** (`page.tsx`), **25 API route handlers** and **93 Server Actions** in 29 files. They are split across a public area and three role spaces. Each space's layout calls a server-side guard, and each page and action checks again.

| Space | Route prefix | Who (server-enforced) | Pages |
|---|---|---|---:|
| Public | `/login`, `/forgot-password`, `/set-password`, `/security/not-me` | Anyone (rate-limited) | 4 |
| My approvals (users) | `/users/**` | USER, IT_ADMIN, SUPER_ADMIN (page access may hide or make view-only, not for Super Admin) | 24 |
| Admin | `/admin/**` | IT_ADMIN, SUPER_ADMIN | 31 |
| Super Admin | `/superadmin/**` | SUPER_ADMIN | 14 |
| Root redirect | `/` | — | 1 |

Roles: `USER`, `EXPORTER` (a download permission, now redundant: AUTH-16), `IT_ADMIN`, `SUPER_ADMIN`. The roles are fixed; custom roles are not built. The break-glass account is a flagged Super Admin with a time window.

### 0. Authorization model (verified)

| Layer | Where | What it checks |
|---|---|---|
| 1. Middleware | `middleware.ts` L71-78 | Session cookie present only; signs the request path into `PATH_HEADER`/`PATH_SIGNATURE_HEADER` (L84-90) for page access |
| 2a. Pages / layouts | `server/authorization/guards.ts` L19-41 `requireArea(area)` | Role per area (`server/authorization/policy.ts` L6-10: users = USER/IT_ADMIN/SUPER_ADMIN, admin = IT_ADMIN/SUPER_ADMIN, superadmin = SUPER_ADMIN), active flag, then page-access level (Hidden -> 404). | 2b. Actions / APIs | `guards.ts` L47-68 `requireApiArea(area, {change})` | Same, plus "change needs FULL" (VIEW blocks Server Actions, detected by `next-action` header, `page-access.ts` L28) |
| Admin action helper | `server/admin/actor.ts` L8-16 `getAdminActor()` | `requireApiArea("admin")` + IP; returns null -> "Not found." |

Every page in scope calls `requireArea` directly, except the three `/admin/analytics/*` pages (see G-1). Every admin Server Action calls `getAdminActor()`; every Super Admin action calls `requireApiArea("superadmin")`; user utility actions call `requireApiArea("users")`.
