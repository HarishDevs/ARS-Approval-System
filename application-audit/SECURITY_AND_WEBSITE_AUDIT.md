# Security and Website Audit (v1.10.0)

**Date:** 16 Oct 2026
**Scope:** the 19 security checks (SEC-01 to SEC-19) and 20 website fixes (WEB-01 to WEB-20) from the owner's brief.
**Baseline:** v1.9.2 (commit e00c5e5).
**Method:** source read of the whole repository, plus the 16 Oct 2026 application audit (`00`–`13` in this folder).

This file records the state **before** the v1.10.0 changes. What was changed, and the evidence, is in `SECURITY_WEBSITE_FIX_TRACKER.md`. The overall result is in `SECURITY_AND_WEBSITE_FINAL_REPORT.md`.

Exploit details are summarised only. The repository is private, but this file is written so it could be shared internally.

## 1. The application as audited

| Area | What is there |
|---|---|
| Framework | Next.js 15.5 App Router, React 19, TypeScript, Tailwind 3.4 |
| Routes | 87 pages; 27 API routes (`app/api/**/route.ts`); Server Actions in 30+ `"use server"` files |
| Areas | `/users` (everyone), `/admin` (IT_ADMIN, SUPER_ADMIN), `/superadmin` (SUPER_ADMIN only), public auth pages |
| Authentication | Google (Firebase ID token verified on the server); User ID + password + WhatsApp OTP. Sessions are signed with HMAC and stored as a DB row (idle limit, 12 h absolute). |
| Authorisation | Three layers: middleware (cookie present), area guards (`requireArea` / `requireApiArea`), record checks (`loadRequestView`, `loadTaskFor`, `loadInfoFor`, `openAttachment`). v1.8.0 adds page access rules (Hidden / View / Full) checked on the server. |
| Database | MySQL 8 via `mysql2`. Parameterised queries. Additive SQL migrations. Append-only triggers on the audit log, timeline and comments. |
| Files | Uploads go to `UPLOAD_DIR` outside the web root. Each file is checked for extension, signature, size and count. Downloads are authorised per record. |
| Public endpoints | Sign-in, password reset, set-password and "not me" flows; `/api/health`; the cron runner (secret); the CEOITBox webhook (secret) |
| Headers | CSP with a nonce per request, `frame-ancestors 'none'`; HSTS; nosniff; Referrer-Policy; Permissions-Policy; X-Frame-Options DENY; COOP same-origin-allow-popups |
| Hosting | GoDaddy Node.js (cPanel) behind Cloudflare. Optional `ORIGIN_SECRET` origin lock. |
| Tests | Vitest unit (451) and integration (203, real MySQL); Playwright E2E (98), QA (27), origin (1); CI on GitHub Actions |

## 2. Security findings (SEC-01 to SEC-19)

Severity reflects the actual risk in this application, not the generic category.

| ID | Requirement | Relevant files / routes | Current implementation | Risk and impact | Severity | Recommended fix | Verification method | Initial status |
|---|---|---|---|---|---|---|---|---|

Isolation is enforced by central SQL visibility rules used by lists, search, pages, PDF and downloads. **Gap:** the CSV user import skipped the contact-change rule (AUD-01), so an IT Admin could change another IT Admin's email and take over that account. | Insider account takeover between IT Admins. | **High** | Apply `checkContactChange` in `planUsers`; add an IDOR browser test. | Unit (import plan), E2E (cross-user 404s) | Partially Implemented |
| SEC-02 | AuthN/AuthZ on every API route | `app/api/**`, `server/authorization/guards.ts`, `page-access.ts` | Every protected route calls `requireApiArea`. Page rules were keyed only on the address an action is posted to (AUD-14 / G-3): an admin action posted from `/superadmin/import`, or from another page sharing the action, skipped a Hidden or View-only rule. No test fails when a new unguarded route is added. | A page restriction could be sidestepped. Role, area and record checks still applied. | **Medium** | Admin actions name their own page key; Super Admin addresses refuse everyone else; static route and action inventory test. | Unit inventory test, integration page-key test | Partially Implemented |
| SEC-03 | Never trust the frontend | services under `server/**` | Identity comes from the session. zod and the engine validate inputs and transitions on the server. One vote per step (v1.9.0).
